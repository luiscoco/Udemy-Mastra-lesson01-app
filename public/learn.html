01

Place Mastra in the stack

Separate your product interface and business rules from orchestration, model providers and data services. The tutor page is the product; the Mastra registry connects its agent and tool.

02

Recognize an agent

Identify its model, instructions and available tools. Follow the bounded loop from a question through a tool result to an explanation.

03

Inspect a typed tool

Read the search description, Zod input schema, implementation and returned source passages. The model chooses arguments; the application validates the boundary.

04

Distinguish context sources

Conversation memory carries information between turns when configured. Retrieval supplies relevant evidence. This app retrieves bundled notes and does not persist a conversation.

05

Know when order matters

A workflow defines steps and branches, such as classify → draft or request a human decision. Our tutor is an agent example; that workflow is introduced conceptually.

06

Verify observed outcomes

Inspect actual application events and source IDs. Traces, structured logs and evaluations serve different purposes; a production telemetry backend is not configured here.

Check your understanding

Is Mastra the language model?

No. Mastra coordinates the application pieces. The configured model provider performs inference.

Does a tool description enforce valid input?

The description guides the model. Runtime schema validation checks the supplied values. Application permissions and scope still need explicit controls.

Does a correct citation ID prove the answer is supported?

No. This application checks that cited IDs came from the tool's results. A student must still read the passages and verify the claims; semantic evaluation is a separate concern.

When is a workflow useful?

When the application needs a defined sequence or branch. A ticket process can fetch data, classify, then draft or wait for a human decision.

Your takeaway: Mastra gives a TypeScript application a coordinated way to use agents, tools, data and workflows. The product still owns its behavior, evidence checks and operational limits.
